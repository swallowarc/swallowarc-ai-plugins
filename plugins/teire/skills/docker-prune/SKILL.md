# docker-prune（停止中のコンテナと未使用イメージの掃除）

## 概要

ローカルの Docker から、停止中のコンテナ（created／exited／dead）と、稼働中のコンテナが使っていないイメージをすべて削除する。
停止中のコンテナだけが使っていたイメージも、そのコンテナと一緒に消える。
判定と削除はこのスキルと同じディレクトリにある `docker-prune.sh` が行う。
自分で `docker rm`・`docker rmi`・`docker system prune` などを組み立てない。

ボリューム・ネットワーク・ビルドキャッシュには触れない。

## 手順

1. 任意のディレクトリで `bash <このスキルのディレクトリ>/docker-prune.sh plan` を実行する。
   何も変更しないコマンドである。
2. 出力をそのまま（省略・要約せず）ユーザーに見せる。
   先頭の `Docker context` 行で、どの Docker デーモンが対象かを本文でも繰り返す。
   ローカル以外（`tcp://`・`ssh://` など）のときは、その旨を明記する。
   停止中のコンテナを消すとコンテナ内に書き込まれたデータは戻せないこと、消したイメージは再 pull か再ビルドが必要なことを明記する。
   「削除対象はありません。」なら、そこで終える。
3. 削除してよいかを確認する。
   AskUserQuestion が使えるなら、質問文に Docker context 名と、削除するコンテナとイメージの件数を入れる（ダイアログの外の本文が読まれない環境があるため）。
   明確な同意がなければ削除しない。
4. 同意が得られたら、plan の出力にあった plan id を渡して `bash <このスキルのディレクトリ>/docker-prune.sh apply <plan id>` を実行する。
   plan id が一致しないと拒否される。拒否されたら手順 1 からやり直し、新しい一覧で再度確認する。
5. apply の出力をそのまま報告する。
   `FAILED` があれば、その行と原因を報告する。自分で `-f` を付けて再試行しない。

## スクリプトが残すもの

- 稼働中・一時停止中・再起動中のコンテナ
- それらのコンテナが使っているイメージ
- ボリューム（停止中コンテナの匿名ボリュームも残る）、ネットワーク、ビルドキャッシュ

これらを消すためにコンテナの停止や `docker volume prune` などを提案・実行しない。必要ならユーザーが自分で行う。

## Red Flags

- plan の出力を見せずに apply する
- Docker context と件数を伝えずに確認を取る
- スクリプトを使わず docker コマンドを手で組み立てて削除する
- 失敗した削除を `-f` などで勝手にやり直す
